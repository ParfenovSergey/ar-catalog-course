AR Catalog — пет-проект мобильного приложения, которое связывает физические объекты с их цифровыми моделями. Пользователь выбирает объект в каталоге или сканирует QR-код, изучает модель в 3D и размещает её в окружающем пространстве с помощью AR.

Проект объединяет мобильный интерфейс, локальное хранение данных, работу с камерой и интеграцию 3D/AR. Такой подход можно использовать для демонстрации предметов, интерактивных экспозиций и каталогов оборудования.

**Статус:** в разработке (0/9). Целевая платформа — Android.

## Сценарий использования

1. Открыть каталог и выбрать объект либо перейти к сканированию QR.
2. Получить сведения об объекте из локальной базы SQLite.
3. Открыть связанную GLB-модель: вращать её и менять масштаб.
4. Перейти в AR, разместить объект на поверхности и рассмотреть его в реальном окружении.
5. Вернуться в приложение к выбранной модели.

QR-код содержит только идентификатор записи. Название, описание и путь к модели приложение получает из базы данных.

## Возможности проекта

- **Каталог объектов** — карточки с превью, названиями и описаниями.
- **Локальное хранение** — SQLite для метаданных и сохранения изменений между запусками.
- **QR-сканирование** — распознавание камерой, проверка идентификатора и поиск объекта.
- **Интерактивный 3D** — просмотр моделей формата GLB с управлением жестами.
- **Дополненная реальность** — запуск модели во внешнем Android Scene Viewer на совместимом устройстве.
- **Анимации интерфейса** — реакции карточек, Hero-переходы и визуальные состояния загрузки.
- **Обработка ошибок** — неизвестный QR, отсутствующая запись, отказ камеры, ошибки загрузки и недоступность AR.

## Интерфейс

Приложение состоит из трёх основных экранов.

| Экран | Задача |
|---|---|
| `HomeScreen` | Каталог объектов, выбор карточки и переход к сканеру |
| `ScannerScreen` | Получение QR, проверка значения и поиск модели |
| `ArScreen` | Информация об объекте, интерактивный 3D и запуск AR |

При успешном сканировании `ScannerScreen` возвращает найденный объект в `HomeScreen`, после чего открывается `ArScreen`. Камера сканера освобождается до перехода к просмотру модели. Вспомогательные действия размещаются в диалогах.

## Архитектура

Проект использует Repository Pattern: интерфейс работает с контрактом `ModelRepository`, а детали хранения остаются в слое данных. Для локального состояния используются стандартные механизмы Flutter.

| Компонент | Ответственность |
|---|---|
| `ArModel` | Данные объекта и проверка их корректности |
| `ModelRepository` | Асинхронный контракт чтения и изменения каталога |
| `SqliteModelRepository` | Рабочее хранилище на SQLite |
| `MemoryModelRepository` | Хранилище в памяти для изолированных тестов и прототипирования |
| `DatabaseService` | Соединение, схема, первоначальное заполнение и миграции БД |
| `QrCatalogService` | Преобразование строки QR в результат поиска объекта |
| `ModelSourceService` | Подготовка локального или HTTPS-источника GLB |

Модель предметной области не зависит от Flutter. Сервисы проверки QR не управляют навигацией, а экраны не содержат SQL-запросов. Такой подход позволяет тестировать логику отдельно от камеры и интерфейса.

| `dart_foundations/` | Консольные эксперименты с моделью данных и репозиторием |

### Данные каталога

В таблице SQLite `ar_models` хранятся идентификатор, название, описание, путь к GLB, путь к превью и начальный масштаб объекта. Сами изображения и модели размещаются в ресурсах приложения.

База создаётся при первом запуске. Первоначальное заполнение не должно перезаписывать сохранённые изменения при последующих открытиях.

### Формат QR

Примеры содержимого: `1`, `2`, `3`.

Допустимы десятичные идентификаторы от `1` до `2147483647`. Краевые пробелы удаляются, ведущие нули допускаются. Пустые значения, знаки, дроби, URL и дополнительные символы отклоняются.

Проверенный идентификатор используется для поиска записи SQLite. Файл выбирается по `modelPath` найденного объекта; адрес модели не зашивается в QR.

```bash
git clone https://github.com/ParfenovSergey/ar-catalog-course.git ar-catalog
cd ar-catalog/ar_catalog
flutter pub get
flutter run
```

При подключении нескольких устройств выберите нужное явно:

```bash
flutter run -d DEVICE_ID
```

`DEVICE_ID` — идентификатор из списка устройств. Для телефона предварительно включите USB-отладку и подтвердите подключение к компьютеру.

## Проверки

Следующие команды выполняются из `ar_catalog/`.

Статический анализ и unit-/widget-тесты:

```bash
flutter analyze
flutter test
```

Проверка форматирования:

```bash
dart format --output=none --set-exit-if-changed lib test
```

Интеграционные тесты на Android:

```bash
flutter test integration_test/database_test.dart -d DEVICE_ID
flutter test integration_test/app_flow_test.dart -d DEVICE_ID
```

Ключевые сценарии проверки: создание и повторное открытие SQLite, поиск отсутствующей записи, некорректные QR, защита от повторной обработки кадров, возврат из фона, загрузка GLB и переход в AR.

Работа физической камеры и размещение модели в реальном окружении проверяются отдельно на устройстве. Тесты с подменёнными зависимостями не заменяют эти проверки.

## Сборка Android

Из `ar_catalog/`:

```bash
flutter build apk --release
```

Результат: `ar_catalog/build/app/outputs/flutter-apk/app-release.apk` относительно корня репозитория.

Для установки с доступным `adb`, находясь в `ar_catalog/`:

```bash
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

Для распространения APK требуется настроенная подпись приложения. Закрытые ключи и пароли хранятся вне репозитория.

## Особенности 3D и AR

**Локальный 3D.** GLB загружаются из `assets/models/`, а превью — из `assets/previews/`. Каталог и просмотр локальных ресурсов рассчитаны на работу без сети.

**Внешний AR.** Android Scene Viewer должен самостоятельно получить файл модели. Доступность Flutter asset внутри приложения не гарантирует доступность этого файла внешнему просмотрщику. В варианте с HTTPS используется прямая ссылка к той же модели, сформированная из базового адреса хостинга и пути из SQLite. Такой запуск зависит от сети.

**Поддержка устройства.** Если AR недоступен, пользователь должен иметь возможность продолжить просмотр в 3D. Открытие внешнего просмотрщика не всегда означает переход в AR: возможен обычный 3D-режим.

**Ресурсы.** GLB и изображения должны быть доступны после клонирования. Для сторонних материалов необходимо сохранять сведения об авторе, источнике и лицензии.
